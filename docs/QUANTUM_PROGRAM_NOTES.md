## reference-published-fukui-may-describe-a-higher-cation-state

*From the assistant's notes (`reference_published_fukui_may_describe_a_higher_cation_state.md`, type: n/a).*  
*A published condensed Fukui f- can belong to a cation state ABOVE the lowest one (anilinium +0.094 eV, benzaldehyde +0.145, thiophene +0.449); the app's N-1 state is whichever the SCF reaches from the neutral's orbitals and benzaldehyde's depended on the geometry - a published-table gate for such molecules measures the SCF landing, not the arithmetic*

Found 2026-10-18 after the second Fukui gate failed (33 of 47 numbers, `benchmarks/fukui_gate_2/PREREGISTRATION.md` 11.4). A post-gate probe (`benchmarks/fukui_gate_2/cation_states_probe.py`) converged each N-1 state with its hole in the neutral's HOMO, HOMO-1, HOMO-2, HOMO-3 (ORCA 6.1.1: `%scf Rotate {HOMO-k, HOMO, 90, 1, 1} end` rotates BETA orbitals in the guess; flags `1,1` work, `0,0` did not) and compared each state's Hirshfeld f- with De Proft 2002.

**What it showed:** the published numbers of anilinium, benzaldehyde and thiophene match a cation state +0.094, +0.145 and +0.449 eV above the lowest ΔSCF state (distance 0.0011-0.0021, against a tolerance of 0.02); the lowest state is 0.05-0.12 away. `route_check.py` ran the application's own compound input on the probe's geometries: benzaldehyde reached the +0.145 state (the published one) where the gate's own geometry had given the lowest; anilinium and thiophene reached the lowest on both. HCN, pyrrole, furan and SCN- (S) are NOT explained by any state tried.

**The landing is not a function of the structure (probes 3 and 4, same day; `core_check.py`, `landing_check.py`, PREREGISTRATION 11.4):** benzaldehyde through the application's own input: identical to 11 digits at 8, 4, 2 and 1 cores (cores are NOT the cause); over 14 runs 6 reached the published-like +0.145 eV state and 8 the lowest: rigid rotations of one geometry 3 of 4 published-like, 0.001 A displacements 0 of 4, five independent optimizations 2 of 5. Every run more than ~0.00025 A RMS out of plane (6 of 6) reached the lowest state; at or below it 6 of 8 reached the higher one. Consistent with a symmetry-held state in a planar geometry (NOT tested; does not explain anilinium/thiophene, whose published state is the HOMO-1 hole). Also seen incidentally: RDKit/MMFF puts CN- at 1.461 A (no geometry); a fixture from it gave f- 0.063 away from the first gate's record - use the ORCA-optimized bond length (1.183918 A at B3LYP/6-31G**).

**Why it matters:** (1) a finite-difference Fukui function is only defined for a chosen N-1 state, and the app takes whatever the SCF lands in from the neutral's orbitals, without looking for a lower one or saying another is close (it does that for anion starts only); (2) a published table can describe a state the lowest-energy rule would not pick, so a gate against it can fail with correct arithmetic; (3) the HOMO/HOMO-1 orbital gap tracks the ΔSCF gap of the competing state (within 0.062 eV over five molecules) but does NOT tell a missing molecule from a matching one (pyrrole 0.835 eV misses, phenol 0.815 eV matches), so no gap threshold is a validated flag.

**How to apply:** when a Fukui/charge-difference number disagrees with a table for a molecule whose two highest occupied orbitals are close, converge the competing hole states before suspecting the code; never claim "lowest of several holes" would reproduce such a table (for these three it picks the state that does NOT match); a v3 that searches holes needs its own preregistration with a reference whose states are identified. ## reference-gbw-remembers-its-path

*From the assistant's notes (`reference_gbw_remembers_its_path.md`, type: n/a).*  
*An ORCA .gbw stores the absolute directory it was created in, and orca_plot follows that path rather than the cwd*

An ORCA `.gbw` records the **absolute path of the job directory it was
created in** — twice in the gbw, three times in the companion
`.densitiesinfo` — and `orca_plot` opens `<that path>/job.densitiesinfo`
rather than looking in the working directory. Move the wavefunction and
delete the original directory and ESP (plot type 43) dies with
`CANNOT OPEN FILE`, exit 64, no cube. Orbitals and electron density never
read that file, so only one surface kind appears broken.

**Why this matters beyond ORCA:** a tool can carry an absolute path
inside a binary artefact, so "I copied the files, why does it fail" has an
answer that no amount of reading the calling code will reveal. Reproduce
the invocation by hand and read the error's *path*, not just its
filename.

Two things measured while fixing it (2026-08-07), both cheap to redo:

- Restoring only `job.densities` + `job.densitiesinfo` at the baked path
  is enough — 37 KB against a 1 MB gbw, which stays in the cwd.
- `orca_plot` compares a density name against its own **fully qualified**
  listing, so bare `job.scfp` is refused. It still writes a cube from the
  fallback density, which is why the refusal hid for months.

**A probe that leaves state behind lies to the next probe.** Having
recreated the baked directory to prove the cause, three later "cold" runs
in fresh directories all passed because that directory still existed,
process-wide and invisible to the test. Delete what a probe created
before believing the next result. Related:
`feedback-verify-real-backends`, `feedback-measure-on-the-target-commit`.
