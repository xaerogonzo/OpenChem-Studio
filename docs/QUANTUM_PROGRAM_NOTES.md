The frozen preregistrations and results themselves live under `benchmarks/`; this page is the working history around them.

These sections were moved here on 2026-10-29 from the assistant's private memory, so they are readable, searchable and versioned with the code. The text is kept as it was written (headings demoted one level, memory links written as plain names); dates and PR numbers are those of the time. Treat a measurement as true of the commit it was made on, and check a file or function named here still exists before relying on it. Where the original text named a commercial product or its vendor, the generic wording the repository uses ("the reference editor", "the vendor") stands in its place, as `tests/test_no_competitor_names.py` requires.

## reference-gbw-remembers-its-path

*From the assistant's notes (`reference_gbw_remembers_its_path.md`, type: n/a).*  
*An ORCA .gbw stores the absolute directory it was created in, and orca_plot follows that path rather than the cwd*

An ORCA `.gbw` records the **absolute path of the job directory it was
created in** — twice in the gbw, three times in the companion
`.densitiesinfo` — and `orca_plot` opens `<that path>/job.densitiesinfo`
rather than looking in the working directory. Move the wavefunction and
delete the original directory and ESP (plot type 43) dies with
`CANNOT OPEN FILE`, exit 64, no cube. Orbitals and electron density never
read that file, so only one surface kind appears broken.

**Why this matters beyond ORCA:** a tool can carry an absolute path
inside a binary artefact, so "I copied the files, why does it fail" has an
answer that no amount of reading the calling code will reveal. Reproduce
the invocation by hand and read the error's *path*, not just its
filename.

Two things measured while fixing it (2026-08-07), both cheap to redo:

- Restoring only `job.densities` + `job.densitiesinfo` at the baked path
  is enough — 37 KB against a 1 MB gbw, which stays in the cwd.
- `orca_plot` compares a density name against its own **fully qualified**
  listing, so bare `job.scfp` is refused. It still writes a cube from the
  fallback density, which is why the refusal hid for months.

**A probe that leaves state behind lies to the next probe.** Having
recreated the baked directory to prove the cause, three later "cold" runs
in fresh directories all passed because that directory still existed,
process-wide and invisible to the test. Delete what a probe created
before believing the next result. Related:
`feedback-verify-real-backends`, `feedback-measure-on-the-target-commit`.
